# Словарь данных

## Основные сущности SQLite

### `student_groups`

- `group_id` — суррогатный первичный ключ;
- `group_name` — нормализованный код вида `ПИ-401`;
- `program_code`, `program_name`, `study_year` — параметры программы.

### `students`

- `student_id` — синтетический ID вида `STU0001`;
- `full_name` — синтетическое ФИО;
- `group_id` — внешний ключ;
- `gender`, `age` — атрибуты для описания, **не используются моделью**;
- `admission_score` — вступительный балл 0–100;
- `previous_gpa` — исторический средний балл 2–5;
- `scholarship` — бинарная отметка, **не используется моделью**.

### `enrollments`

Одна строка на сочетание студент × дисциплина × семестр. `midterm_score` и `assignment_score` доступны модели; `final_score` и `final_grade` нужны только для формирования факта после семестра.

### `lms_events`

Событийный журнал: временная метка, тип, длительность, признак своевременной отправки. Индекс `(student_id, event_ts)` ускоряет временные выборки.

### `attendance`

Одна отметка на студент × дисциплина × дата. `present` и `late` бинарные.

### `student_features`

| Поле | Смысл | В модели |
|---|---|:---:|
| `admission_score` | вступительный балл | ✓ |
| `previous_gpa` | средний балл прошлых семестров | ✓ |
| `attendance_rate` | доля присутствий | ✓ |
| `late_rate` | доля опозданий | ✓ |
| `lms_events_per_course` | событий LMS на дисциплину | ✓ |
| `active_days` | уникальные активные дни | ✓ |
| `avg_session_minutes` | средняя длительность события | ✓ |
| `submission_on_time_rate` | доля отправок вовремя | ✓ |
| `quiz_attempts_per_course` | попыток тестов на дисциплину | ✓ |
| `forum_posts_per_course` | сообщений форума на дисциплину | ✓ |
| `midterm_avg` | средний промежуточный балл | ✓ |
| `assignment_avg` | средний балл заданий | ✓ |
| `attempts_avg` | среднее число попыток сдачи | ✓ |
| `low_midterm_share` | доля дисциплин с баллом < 50 | ✓ |
| `at_risk` | хотя бы одна итоговая оценка 2 | цель |
| `failed_courses` | число итоговых двоек | ✗ |
| `final_gpa` | итоговый средний балл | ✗ |

### `model_runs` и `predictions`

`model_runs` хранит версию, алгоритм, порог и тестовые метрики. `predictions` привязан одновременно к студенту и версии модели; содержит вероятность, уровень и JSON с локальными факторами.

### `query_logs`

Технический журнал: время, сессия, роль, намерение, запрос длиной до 500 символов, задержка, статус, число результатов и факт применения LLM. В продуктивной системе текст запроса следует минимизировать или псевдонимизировать по утверждённой политике хранения.

### `data_quality_log`

Аудит проверок ETL: источник, правило, число затронутых записей и выполненное действие.
